## Project Overview

ROS Noetic + Gazebo motion planning framework with integrated RL training. Ubuntu 20.04. The system uses `move_base` as the navigation backbone, with custom global planners and local controllers registered as plugins. RL training pipeline uses **TD3** algorithm to train agents navigating in Gazebo by directly controlling `cmd_vel`, bypassing `move_base` for the trained robot while optionally using `move_base` for opponent robots.

> **注意：PPO 算法已不再使用，当前主要使用 TD3 进行训练。** PPO 相关代码（`train_new.py`、`RosGazeboEnv`、`rsl_rl` 中的 `OnPolicyRunner`）仍保留在代码库中但已废弃。

## Configuration System

**All robot/planner/world configuration flows through `src/user_config/user_config.yaml`**. Do NOT edit launch files directly — they are auto-generated by `src/plugins/dynamic_xml_config/main_generate.py` each time `main.sh` runs.

Key config fields in `user_config.yaml`:
- `map` / `world`: Gazebo world and 2D map name (must match filenames in `src/sim_env/worlds/` and `src/sim_env/maps/`)
- `robots_config`: List of robots with type, global_planner, local_planner, and spawn pose
- `plugins`: Optional pedestrian, obstacle, and map layer configs

RL training configs live in `src/rl_training/config/` (e.g., `forklift_movebase.yaml`). These define env observations, reward, spawn ranges, opponent settings, and algorithm hyperparameters. The training scripts also read `user_config.yaml` to extract robot init poses.

## Architecture

### Core C++ Packages (`src/core/`)

- **`path_planner`** — `move_base` `BaseGlobalPlanner` plugins. Factory pattern in `path_planner_factory.cpp` selects algorithm by name. Also includes `nomad_planner` which calls an external Python diffusion service via ROS service `/nomad/make_plan`.
- **`controller`** — `move_base` `BaseLocalPlanner` plugins. Includes DWA, PID, APF, RPP, LQR, MPC, ORCA, and **`ppo_controller`** which subscribes to external `cmd_vel` from the RL agent (pass-through mode for training/inference).
- **`common`** — Shared geometry (curves: Bezier, B-spline, Dubins, Reeds-Shepp), collision checking, math helpers, visualization.

### Global Planners (20+ algorithms)

| 类别 | 算法 |
|---|---|
| **图搜索** | A*, Dijkstra, GBFS, JPS, 双向 JPS, D*, D* Lite, LPA*, Theta*, S-Theta*, Lazy Theta*, Hybrid A*, Voronoi, Lazy |
| **采样类** | RRT, RRT*, RRT-Connect, Informed RRT*, Quick Informed RRT* |
| **进化算法** | ACO（蚁群）, PSO（粒子群）, GA（遗传算法） |
| **扩散模型** | NoMaD（视觉导航 Transformer，通过 `/nomad/make_plan` ROS 服务调用） |

All registered via factory pattern in `path_planner_factory.cpp`.

### Local Controllers (9 types)

| 控制器 | 说明 |
|---|---|
| **DWA** | Dynamic Window Approach — 速度空间采样 |
| **PID** | PID 路径跟踪控制器 |
| **APF** | Artificial Potential Field — 人工势场 |
| **RPP** | Regulated Pure Pursuit — 纯追踪 |
| **LQR** | Linear Quadratic Regulator |
| **MPC** | Model Predictive Control |
| **ORCA** | Optimal Reciprocal Collision Avoidance — 多机器人避碰（使用 RVO2 库） |
| **Static** | 静止控制器 |
| **PPO** | RL 透传桥接器 — 接收外部 `cmd_vel` 并通过 `move_base` 转发 |

### Simulation Environment (`src/sim_env/`)

- `worlds/`: Gazebo `.world` files (warehouse, museum, workshop variants with pedestrians/obstacles)
- `maps/`: 2D occupancy grid maps for `map_server`
- `urdf/`: Robot models — forklift, pioneer3dx, nanocar, turtlebot3 variants
- `config/`: `move_base_params.yaml`, costmap params, AMCL params, per-robot overrides in `config/robots/<type>/`
- `launch/`: `config.launch` is the main entry. `start_robots.launch.xml` is auto-generated and recursively spawns N robots.

### RL Training (`src/rl_training/`) — 主要使用 TD3

**当前活跃的训练管线：TD3 (Twin Delayed DDPG)**

#### 训练环境：`MoveBaseGazeboEnv` (`envs/movebase_gazebo_env.py`)

**观测空间（24 维）：**
- 20 波束激光雷达（180 原始值 → 20 扇区 min-pooling，归一化到 [0, 1]）
- 4 个辅助值：`[目标距离, 航向误差 θ, 上一步线速度, 上一步角速度]`

**动作空间（2 维）：**
- `action[0]`: 线速度 x → 映射为 `(action[0]+1)/2` → [0, 1] m/s
- `action[1]`: 角速度 z → [-1, 1] rad/s

**同步步进机制：**
```
发送动作 → unpause_physics → sleep(control_dt=0.1s) → pause_physics → 计算奖励/观测
```

**奖励设计：**
| 条件 | 奖励 |
|---|---|
| 到达目标（距离 < 0.3m） | **+100**（终止） |
| 碰撞（最近扫描 < 0.35m） | **-100**（终止） |
| 中间步骤 | `linear_vel/2 - abs(angular_vel)/2 - r3(min_scan)/2 - 0.1` |

其中 `r3(x) = 1-x if x<1 else 0`，惩罚靠近障碍物。整体设计鼓励前进、惩罚旋转和接近障碍、恒定步骤代价促进效率。

**课程学习：**
- 目标采样窗口从 ±2m 逐步扩大到 ±10m（每次 reset 增长 0.004m）
- 约 2000 次 reset 到达最大范围

**探索策略：**
- 初始噪声 1.0，线性衰减到 0.1（经 500,000 步）
- 15% 概率在靠近障碍时执行 8-15 步随机后退动作

**卡住检测：**
- 若 `dist_to_goal`（精度 0.1m）连续 50 步不变，强制 reset

#### TD3 网络结构 (`third_party/drl_td3/`)

- **Actor**: 3 层 MLP `state_dim → 800 → 600 → action_dim`，ReLU + Tanh 输出
- **Critic**: 双 Q 网络，状态分支 + 动作分支非标准融合（权重乘法而非拼接）
- 训练参数：`batch_size=40, γ=0.99999, τ=0.005, buffer_size=1,000,000`

#### 对手机器人

- 启用时，`robot2` 在目标附近 [3.0, 5.0]m 处生成
- 通过 `move_base` 自主导航，作为动态障碍

#### 已废弃：PPO 训练管线

> PPO 相关组件（`train_new.py`、`RosGazeboEnv`、`ResActorCritic`）已**不再使用**，代码仍保留在仓库中供参考。PPO 之前使用 `rsl_rl` 的 `OnPolicyRunner`，带残差块网络。

### Plugin System (`src/plugins/`)

- **`dynamic_xml_config`** — Python scripts that read `user_config.yaml` and generate launch XML files (robot spawning, planner selection, map loading). This is why launch files should not be hand-edited.
- **`dynamic_rviz_config`** — Auto-generates RViz config based on robot count.
- **`gazebo_plugins`** — Pedestrian Social Force Model (SFM) plugin for dynamic obstacles.

### Key Data Flow

```
user_config.yaml
  → dynamic_xml_config generates start_robots.launch.xml
  → config.launch loads Gazebo world + map_server + spawns robots with move_base
  → Each robot gets: URDF spawn + AMCL + move_base (global_planner + local_planner)
  │
  ├── Robot1 (RL 智能体):
  │     Global Planner: theta_star (用于路径可视化，RL 不直接使用)
  │     Local Planner: ppo_controller (透传桥接器)
  │     RL env 直接发布 cmd_vel 到 /robot1/cmd_vel
  │     观测: /robot1/scan (180 beams → 20 min-pooled) + /robot1/odom
  │
  └── Robot2 (自主对手):
        Global Planner: diffusion (NoMaD 服务调用)
        Local Planner: pid (标准路径跟踪)
        目标由 RL env 通过 /robot2/move_base_simple/goal 设定
```

## Important Patterns

- Robot namespacing: all topics are prefixed `/<robotN>/` (e.g., `/robot1/scan`, `/robot1/cmd_vel`)
- The RL env uses Gazebo `pause_physics`/`unpause_physics` to achieve synchronous stepping — each `env.step()` unpauses for `control_dt` seconds then re-pauses
- Spawn and goal positions are validated against the occupancy grid map to avoid placing robots inside walls
- TD3 uses an expanding goal window (`goal_span` grows from [-4,4] to [-9,9]) as training progresses
- The `ppo_controller` C++ plugin acts as a bridge: it receives `cmd_vel` from the RL Python process and passes it through `move_base`'s local planner interface

## Project Highlights

1. **算法库极其丰富** — 涵盖 20+ 种全局规划 + 9 种局部控制器，几乎覆盖经典运动规划所有主流算法
2. **RL + 传统规划混合** — RL 智能体与传统规划对手共存，形成真实动态场景
3. **课程学习** — 目标距离从近到远逐步增大，让 RL 智能体渐进式学习
4. **插件化设计** — 新增算法只需注册到工厂类，配置文件切换即可
5. **配置驱动** — 单一 YAML 文件控制全部仿真参数，自动生成 launch 文件
6. **NoMaD 扩散模型集成** — 前沿视觉导航 Transformer 作为全局规划器接入 `move_base`
